# Xself Home — Product Display Rules

Source-of-truth document for how products are produced, transformed, and rendered in the Xself Home app. Derived from the reviewer-only audit (15 categories, ~80 cataloged rules). Authoritative on conflict with task instructions; lower than `CLAUDECODE_RULES.md` (change discipline) and `DESIGN.md` (UI style).

## Reading guide

- **Layer** — where the rule lives:
  - `I` import-time (normalize pipeline; one-shot at ingestion)
  - `A` adapter-time (`detailProductAdapter.ts`; runs every read)
  - `R` app-runtime (React component render)
  - `D` database view (`sellable_products`)
- **SoT** — single source of truth for the rule. The rule may run elsewhere as defense-in-depth, but only the SoT may be edited to change behavior.
- **Citations** use `file:line` or column names.
- **Protected systems** (Review, Recommendation, Category, Search) per `CLAUDECODE_RULES.md` must not be modified by changes that follow this doc unless a task explicitly authorizes it.

| Field | Value |
|---|---|

| **Produced at** | Import time, by `cleanTitle()` and `buildDisplayTitle()` |

### 1.2 Price display

| Field | Value |
|---|---|
| **SoT** | `detailProductAdapter.ts:260` (price ladder) + `products.ts:91-93` (`formatPrice`) |
| **Produced at** | Import time (`price` from supplier) + adapter time (resolves `customerPrice`) |
| **Produced from** | `standardized_products.price` (supplier cost), `selling_price` (AI-managed retail, **owner: external to normalize**), `selectedVariant.price` (per-color) |
| **Customer-facing price (ladder)** | `customerPrice = (selling_price > 0) ? selling_price : price` |
| **Detail-screen variant override** | `displayPrice = selectedVariant?.price ?? customerPrice` |
| **Formatting** | `formatPrice(n)` → integer string with thousand separators, **zero decimals**. Currency symbol (`$`) is rendered by the consuming component, not by `formatPrice`. |
| **Displayed at** | Home cards, Discover/Collection tiles, Detail, Cart row, Cart summary (subtotal/shipping/total), Checkout, Order Success, Recommendations, FBT |
| **Layer** | `I` writes raw price; `A` resolves ladder; `R` formats |
| **Allowed** | Reading `product.price` (already the resolved customerPrice), passing through `formatPrice`, multiplying by qty in cart |
| **Not allowed** | Re-deriving customerPrice in UI code (use what the adapter provides); displaying cents at retail surfaces; injecting promotional copy into price strings; computing prices from `inventory_cache` or other non-`standardized_products` sources |

### `selling_price` rules

- **`selling_price` is generated by the dynamic-pricing engine** (`supabase/functions/dynamic-pricing/index.ts`, documented in `pricing/DYNAMIC_PRICING.md`). It applies a tiered cost-markup formula with payment-fee gross-up and psychological rounding — never `price + 150` and never `price * 1.5`. No app-side or normalize-side code may write `selling_price`.
- **Variant backfills must not expose supplier cost as app retail price.** When import scripts insert new color/style siblings, the rows initially land with `selling_price = NULL`. Because the customer-facing ladder falls back to `price` (= supplier wholesale cost) when `selling_price` is null, leaving a row unpriced leaks cost as retail. This is forbidden.
- **If a backfilled variant has no `selling_price`, it must inherit the existing family `selling_price` when one exists.** Selection uses `selectFamilySellingPrice` (`src/services/productResolvers.ts`) — mode across siblings, ties → higher. The family scope is the longest shared SKU prefix between the new variant and its source row.
- **Do not invent a new pricing formula in import scripts.** Inheriting an existing value is allowed; computing a brand-new price (e.g., `cost * 1.5`, `cost + 150`, or any other ad-hoc rule) is not. All net-new pricing decisions belong to the dynamic-pricing Edge Function.
- **Do not set `selling_price = price` unless explicitly running the deprecated v1 migration** (`supabase/dynamic_pricing.sql:17-20`). That migration was a one-shot seed when the column was first added; it must not be re-run except as part of an explicit, documented data-migration step.

### 1.3 Original price / discount

| Field | Value |
|---|---|
| **SoT** | `detailProductAdapter.ts:262-264` (strikethrough rule) + `normalizationPipeline.ts:181-219` (price-ladder source) |
| **Produced at** | Import time for `original_price`; adapter time for the user-visible compare-at and `discountPercent` |
| **Pipeline rule** | `original_price` is set when (1) `discountedPrice < listPrice` (genuine GIGA discount → original=list), else (2) `srpPrice > price` (SRP-anchored → original=SRP), else (3) `spring_sale_original_price > price` (campaign-anchored). Otherwise null. |
| **Adapter rule** | `originalPrice = (r.original_price > customerPrice) ? r.original_price : undefined`. **Strikethrough is shown only when original_price is strictly greater than the customer-facing price.** |
| **Discount percent** | Computed at adapter time: `discountPercent = round((1 - customerPrice / originalPrice) * 100)`. Zero when no original. |
| **Displayed at** | Cards (strikethrough next to price), Detail (compare-at + percent badge), Cart line items, FBT savings sum |
| **Style** | `originalPrice` style: `color #9CA3AF`, `textDecorationLine: 'line-through'` (`App.tsx:2981`) |
| **Layer** | `I` writes `original_price`; `A` produces final `originalPrice` + `discountPercent`; `R` renders |
| **Allowed** | Reading `product.originalPrice` and `product.discountPercent` from the adapter |
| **Not allowed** | Recomputing `discountPercent` in components (see §4 Deprecated). Faking strikethrough when `original_price` is null. Setting `selling_price` from app code. |

### 1.8 Image selection

| Field | Value |
|---|---|
| **SoT** | `imageSelector.ts` (`collectImages`, `BAD_IMAGE_KEYWORDS`) + `NORMALIZATION_ENGINE.md:194-200` |
| **Produced at** | Import time for `primary_image` + `gallery_images_json`; adapter time for the mirror gate |
| **Sources allowed** | ONLY `raw_payload.mainImageUrl` and `raw_payload.imageUrls`. `row.images` / `fileUrls` is **forbidden** (may contain PDF files from suppliers). |
| **Deny keywords (import-time)** | `label, manual, instruction, detail, details, size, spec, specification, specifications, cert, test, warning, pdf, assembly, carton, package, dimension, dimensions, prop65, closeup, close-up, parts, installation, step, guide, barcode, sticker, document, certificate, report, tcps, care, paper, card, carta, description, shooting, lighting, difference` (`imageSelector.ts:11-19`) |

| **Displayed at** | All card thumbnails (primary), Product Detail carousel (primary + gallery), Order/Cart line items (primary), Image search results |
| **Layer** | `I` produces ranked list; `A` applies mirror gate and dedups; `R` renders via `expo-image` |
| **Allowed** | Rendering via `variantUrl` / `originalUrl` helpers; respecting `primaryImageBlurhash`, `primaryImageW/H/Aspect`, `primaryImageMirrorPath` metadata |

### 1.11 Inventory visibility

| Field | Value |
|---|---|
| **SoT** | `supabase/inventory_source_of_truth.sql` (the `sellable_products` view + the refresh functions) |
| **Produced at** | Database (view materialized on read; status maintained by RPCs called from sync scripts and pg_cron) |
| **Gate (sellable_products view)** | `normalization_status='done' AND published AND inventory_status='in_stock' AND total_available_qty>0 AND primary_image IS NOT NULL AND primary_image<>'' AND price>0` |
| **`inventory_status` derivation** | Reads only `inventory_cache.source_type='website_scrape'` rows. `'in_stock'` if fresh + qty>0; `'out_of_stock'` if fresh + qty=0; `'stale'` if last sync >24h; `'unknown'` if no scrape rows ever. |
| **Auto-publish** | `refresh_product_inventory_status()` sets `published = (status = 'in_stock')`. App-side code never sets `published`. |
| **Staleness sweep** | `sweep_stale_inventory()` flips rows to `'stale'` after 7 days but **keeps `published=true`** — checkout enforces its own 24h freshness gate via `validate-checkout-inventory`. |
| **Soft freshness column** | `sellable_products.inventory_freshness` (`fresh / stale / missing / expired`) is for UI badges only — NOT a visibility gate. |
| **Displayed at** | Home, Discover, Collection (query `sellable_products` directly); Product Detail (route through family loader, which reads `standardized_products` but inherits the gate via the view's preceding filter) |
| **Layer** | `D` (view definition) |
| **Allowed** | Reading `sellable_products` for any listing surface; reading `inventory_freshness` for badges; trusting `inventory_status`/`total_available_qty` columns |
| **Not allowed** | Computing visibility in app code; filtering `standardized_products` directly for listing screens (use the view); writing to `published`, `inventory_status`, `has_valid_inventory`, or `inventory_last_synced_at` from app code |

## 2. Marketplace-only rules (excluded)

These rules live in supplier ingestion / marketplace export scripts and must **NOT** influence app product display, except through one well-defined boundary: normalization writes into `standardized_products`, which the app then reads.

| Script | What it does | Boundary |
|---|---|---|
| `scripts/syncGigaFurnitureInventory.ts` | Scrapes warehouse stock via Playwright, writes `inventory_cache`, calls `refresh_product_inventory_status` | Database-only (inventory). No display data mutation. |
| `scripts/syncGigaFurnitureCatalog.ts` | Writes `giga_products` (back-of-house catalog index) | Not app-visible. |
| `scripts/syncNewArrivals.ts` | Feeds `supplier_products` via the same normalize path | Output indistinguishable from regular ingestion — flows through `normalizeProduct()`. |
| `scripts/syncPickup.ts`, `syncGigaInventoryXhr.ts`, `syncGigaWarehouseInventoryHttp.ts`, `importGigaInventoryCurl.ts`, etc. | Supplier-side fetchers | Upstream of normalize. |
| `scripts/setupSpringCollection.ts` | Sets `spring_sale_original_price` in `raw_payload` | Consumed by normalize; campaign pricing flows through `original_price`. |
| `scripts/syncGigaVariants.ts` | Variant backfill — API + Playwright fallback; has its own image deny-list (`NON_PRODUCT_RE`, `PRODUCT_HOST_RE`) | Marketplace-scope filter; must not be relied on at runtime. Long-term: consolidate with `imageSelector.ts` deny-list. |
| `scripts/normalizeProducts.ts` | Batch runner for `normalizeProduct()` | The boundary itself. |
| `scripts/seedGeneratedReviews.ts`, `reviewGenerator.ts` (when run from scripts) | Generates seed review data | Writes into Review System tables — protected. |
| OfferUp / Facebook Marketplace exports (any future) | External marketplace listing generators | If created, must read from `standardized_products` and never write to it. Marketplace-specific copy (e.g. listing template variants, marketplace-specific SKU formats) belong in the export script alone and must not appear in the app. |

**Rule:** any marketplace-only logic — copy templates, listing formats, supplier-side deny-lists, marketplace pricing rules — must remain confined to its script. If marketplace logic affects what the app shows, it must do so by first writing through `normalizeProduct()` into `standardized_products`. The app reads `sellable_products` and `standardized_products` only.

## 3. Layer summary

```
supplier_products (raw B2B row)
       │
       ▼  normalizeProduct()                      [I — import-time SoT]
standardized_products (clean retail rows)
       │
       ▼  refresh_product_inventory_status        [D — database SoT]
sellable_products (the runtime visibility gate)
       │
       ▼  adaptStandardizedRow()                  [A — adapter-time SoT]
Product (app shape)
       │
       ▼  React components                        [R — runtime render]
UI surfaces (Home, Discover, Detail, Cart, etc.)
```

The adapter is the **only** runtime transformation point. Anything done in components must be presentation-only.

## 4. Deprecated / invalid behavior

Marked for cleanup in a future writer pass. Do not introduce new code that uses these patterns.

| ID | Behavior | Location | Why deprecated | Replacement |
|---|---|---|---|---|
| **DEP-1** | Runtime discount-percent recompute | `App.tsx:770-771` recomputes `(originalPrice - price) / originalPrice` at render time | Adapter already writes `discountPercent` using a different formula — two formulas can disagree | Use `product.discountPercent` from the adapter |
| **DEP-2** | Hardcoded SKU placeholder `'XSF-XXXX'` | `App.tsx:1562` | Visible to users when no variant exists; misleading | Render `product.skuCustom ?? '—'` |
| **DEP-3** | Hardcoded `rating: 4.6, reviewCount: 24` | `detailProductAdapter.ts:303-304` | Identical fake numbers on every product; misleads users and biases `recommendationScore` | Integration with Review System aggregate (PROTECTED — coordinate via task authorization) |
| **DEP-4** | `stock: 999` family variant fallback | `productFamilyService.ts:69` | Hides real inventory in variant picker | Propagate `r.total_available_qty` per row |
| **DEP-5** | Duplicated image deny-lists | `imageSelector.ts:11-19` (`BAD_IMAGE_KEYWORDS`) and `scripts/syncGigaVariants.ts` (`NON_PRODUCT_RE`) | Drift risk — `bannerDesign` is in the scraper list but not the normalize list | Extract to one shared module (e.g. `src/utils/imageDenyList.ts`); import from both sites |
| **DEP-6** | Title-derived-only family grouping as the long-term authority | `familyKeyGenerator.ts` algorithm | Fragile when supplier titles diverge across siblings; observed failure during N710P206904 backfill | Add `parent_supplier_product_id` (supplier-rooted family identifier) as a secondary, more durable key. `product_family_key` stays for backward compat. |
| **DEP-7** | Mock product list shipped in app bundle | `src/data/products.ts:108+` | Production reads from `sellable_products`; mock data is dead weight that can be imported accidentally | Delete the array; keep `Product` interface + `formatPrice` exports |
| **DEP-8** | UI-side spec re-formatting as documented practice | `App.tsx:1018-…` `formatSpecValue` | Pipeline already pre-formats Dimensions/Weight; UI helper is defensive but violates "no UI-side formatting" rule | Keep as idempotent fallback for legacy rows; do not extend; document explicitly in `NORMALIZATION_ENGINE.md` as a transitional measure |

These items are flagged here so any reviewer (human or automated) can spot regressions and reject PRs that reintroduce the pattern. Per `CLAUDECODE_RULES.md`, none of them may be touched outside a task that explicitly authorizes the change.
